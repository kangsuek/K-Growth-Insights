# 01. PRD — K-Growth Insights

> 이 문서는 **현재 구현되어 있는 기능**을 기준으로 작성한 제품 요구사항 정의서다. 신규 기획이
> 아니라 as-built 스냅샷이며, 기준 시점은 2026-08-31(백엔드 pytest 229건, 프론트 vitest 397건
> 통과)이다. 코드가 바뀌면 이 문서도 함께 갱신해야 한다. 상세 아키텍처·API·개발 규칙은
> [README.md](../README.md), [CLAUDE.md](../CLAUDE.md) 참고.

## 1. 개요

**K-Growth Insights**는 한국 고성장 섹터 ETF·주식을 개인이 스스로 추적·분석하기 위한
로컬 우선(local-first) 애플리케이션이다. 웹(React+Vite)으로 쓰거나 macOS 데스크톱 앱
(Electron)으로 실행하며, 모든 시장 데이터는 **네이버 모바일 API**에서 수집해 **로컬
SQLite 파일 하나**에만 저장한다. 외부로 전송하는 서버가 없고 계정 가입도 없다.

**대상 사용자**: 본인이 직접 종목을 등록·관리하는 개인 투자자 1인. 다중 사용자·인증·권한
개념은 없다.

**플랫폼**: 웹(개발 서버, `:5173`/`:8000`) 및 macOS 데스크톱(Electron이 `uv`로 백엔드를
사용자 워크스페이스에 구동).

## 2. 목표 / 비목표

### 목표
- 관심(추적) 종목의 시세·수급·펀더멘털·뉴스·인사이트를 한 화면에서 확인한다.
- 시총 상위 종목 유니버스를 대상으로 조건 기반 종목 발굴(스크리닝)을 지원한다.
- 종목 간 비교, 과거 가정 투자 시뮬레이션, 실제 보유 포트폴리오 분석을 지원한다.
- 데이터를 로컬 SQLite 파일 하나에만 저장하고 외부 서버·계정 없이 동작한다.

### 비목표 (이번 범위에서 다루지 않음)
- 실시간 체결·호가 스트리밍(WebSocket) — 폴링 기반 최신 데이터만 제공한다.
- 자동매매·증권사 주문 연동.
- 코스피·코스닥 외 해외 시장.
- 다중 사용자·인증·권한 관리.
- 발굴 카탈로그 전 종목(약 4,300개)의 수익률·수급 전수 수집(비용 문제로 상위 종목만, §8 참고).

## 3. 용어

| 용어 | 뜻 |
|---|---|
| 추적 종목 (watchlist) | 사용자가 설정 화면에서 등록한 관심 종목. DB `stocks` 테이블이 원본(source of truth) |
| 발굴 카탈로그 | 종목 발굴 화면이 대상으로 하는 시총 상위 전체 종목 유니버스. DB `stock_catalog` 테이블, 추적 종목과 별개 |
| RAG context | AI 프롬프트 생성 시 DB에서 조회해 프롬프트 문자열에 삽입하는 시세·수급·뉴스·펀더멘털 데이터 |
| 기준 거래일 | 시세·수익률·수급이 공통으로 참조하는 거래일. 장 마감(15:40 KST) 전에는 전일이 기준 |

## 4. 기능 요구사항

### 4.1 대시보드 (`/`)
- **FR-1.1** 시장 현황: 코스피·코스닥 지수 현재가·등락률 표시. 지수 클릭 시 모달을 띄워
  기간(분봉/1개월/3개월/6개월/1년/3년) 차트와 선택 기간의 등락률("기간 변화")을 보여준다.
- **FR-1.2** 추적 종목 히트맵: 종목별 종가·일간·주간 등락률을 색상으로 표현한 트리맵.
- **FR-1.3** 추적 종목 카드 그리드: 종목별 현재가·등락률·시가/고가/저가·거래량·주간수익률을
  일괄 조회(`POST /api/etfs/batch-summary`)해 카드로 표시한다. 카드마다 최근 14일 미니
  가격 차트, 최근 거래일 매매동향(개인/기관/외국인 순매수), 최근 뉴스 헤드라인 1건 + 건수를
  함께 보여준다. 정렬 기준(설정 순서/타입순/이름순/테마순/사용자 지정 순서)을 화면에서
  바로 전환할 수 있다.
- **FR-1.4** 추천 카드 5종(프리셋): 주간수익률 상위, 외국인 순매수 상위, 기관 순매수 상위,
  거래량 상위, 주간 하락 상위(역발상). 발굴 카탈로그 기준으로 상위 N개를 보여준다.
- **FR-1.5** 자동/수동 새로고침: 자동 새로고침은 **조회만** 재요청하고 전체 데이터 수집을
  트리거하지 않는다. 전체 수집은 수동 버튼("모든 데이터 새로고침")으로만 실행한다.

### 4.2 종목 상세 (`/etf/:ticker`)
- **FR-2.1** 투자 인사이트 요약: 1주/1개월/YTD 수익률과 연환산 변동성으로 전략을 판정한다
  (비중확대 > +10%, 보유 > +5%, 관망 > -5%, 그 외 비중축소). "투자 전략"·"핵심 포인트"·
  "리스크 요약" 3개 카드로 나눠 보여주며, 리스크는 뉴스에서 감지한 키워드(규제/관세/금리/
  환율/경기)를 근거로 표시한다.
- **FR-2.2** 일별 캔들 + 거래량 차트: 기간 프리셋(7일/1개월/3개월/6개월/YTD/1년) 또는
  커스텀 날짜 범위를 선택할 수 있다.
- **FR-2.3** 매매동향 차트: 외국인·기관·개인 순매수, 외국인 보유비중.
- **FR-2.4** 보조지표: RSI·MACD를 체크박스로 개별 켜고 끌 수 있다. RSI는 과매수(70+)/
  과매도(30-)/추세 구간 해설을, MACD는 추세·매수·매도 신호 배지와 골든/데드크로스 해설을
  함께 표시한다.
- **FR-2.5** 분봉 차트(당일/최근 세션, "오늘의 가격 흐름" 요약 포함, 필요 시 자동 수집
  트리거).
- **FR-2.6** 뉴스 타임라인: 날짜별로 그룹핑해 펼침/접힘으로 표시(네이버 검색 API 키가
  있을 때만 활성화).
- **FR-2.7** 펀더멘털: 주식은 PER/PBR/EPS/BPS/배당수익률/시가총액/52주 최고·최저, ETF는
  NAV/괴리율/보수/수익률/구성종목 Top10. 수집된 데이터가 없는 종목은 카드 자체를 표시하지
  않는다(빈 값으로 채우지 않음).
- **FR-2.8** 원본 일별 시세 데이터 표: 최근 N건을 펼치기/접기로 확인할 수 있다.

### 4.3 종목 발굴 (`/scanner`)
- **FR-3.1** 조건 검색: 시장(KOSPI/KOSDAQ/ETF/전체), 종목명·코드 검색, 섹터, 주간·월간·
  연간 수익률 범위, 상승(+) 토글 6종(금일·주간·월간·연간·외국인·기관, "모두 상승" 일괄
  버튼 포함), 지속 상승추세 필터, 정렬(10개 컬럼 중 선택 + 오름/내림차순), 필터 초기화
  버튼, 결과는 **테이블 뷰/히트맵 뷰** 중 선택해 볼 수 있다. 페이지네이션(페이지당 최대
  50건). 필터 영역에 마지막 지표 갱신 시각을 표시한다.
- **FR-3.2** 테마 탐색: 종목명 기반 자동분류 23개 섹터, 섹터별 평균 수익률 내림차순 정렬.
- **FR-3.3** 추천 프리셋 5종(대시보드 FR-1.4와 동일 로직 재사용).
- **FR-3.4** 카탈로그 지표 수집(수동 트리거): ETF→코스피→코스닥 3단계 진행률 폴링, 취소 가능.
- **FR-3.5** 수집 범위 제약: **전체 ETF + 코스피 시총 상위 200 + 코스닥 상위 300**만
  수익률·수급을 채운다(`scanner.KOSPI_TOP_N_SUPPLY` / `KOSDAQ_TOP_N_SUPPLY`). 그 외 종목은
  현재가·거래량만 채워지고 수익률·수급은 비운다.

### 4.4 비교 (`/compare`)
- **FR-4.1** 추적 종목 중 **최소 2개, 최대 20개**를 체크박스로 선택해 정규화 가격 추이를
  한 차트에서 비교.
- **FR-4.2** 위험-수익 산점도, 종목 간 상관관계 히트맵.
- **FR-4.3** 성과 비교 통계 요약(수익률·변동성 등, `comparison.py`).
- **FR-4.4** 선택한 종목별로 투자 시뮬레이션(§4.5) 카드가 비교 화면 안에 바로 표시된다.

### 4.5 시뮬레이션 (`/simulation`)
- **FR-5.1** 일시투자: 특정일에 특정 금액을 매수했다면 현재 평가액이 얼마인지 계산.
- **FR-5.2** 적립식(DCA): 매월 지정일에 정액 매수를 반복했을 때의 결과를 기간을 지정해 계산.
- **FR-5.3** 포트폴리오 배분: 종목별 비중을 지정해 배분 투자했을 때의 결과를 계산.
- 세 시뮬레이션 모두 시세가 없는 미래·범위 밖 날짜로 조용히 폴백하지 않는다(요청 범위를
  벗어나면 값을 만들지 않음).

### 4.6 포트폴리오 (`/portfolio`)
- **FR-6.0** 매입정보(매입가·수량)가 등록된 추적 종목이 하나도 없으면 안내 화면("투자
  종목이 없습니다")만 표시하고, 설정 화면으로 이동하도록 유도한다.
- **FR-6.1** 매입정보(매입일·매입가·수량)가 등록된 추적 종목의 투자금·평가액·손익·비중을
  집계한다.
- **FR-6.2** 수익률 추이, 종목별 기여도를 보여준다.
- **FR-6.3** AI 투자분석 프롬프트 생성: 종목 1개 또는 여러 개를 선택해 DB 데이터(RAG
  context — 최근 시세·수익률·수급·뉴스·펀더멘털)를 결합한 프롬프트를 서버가 생성한다.
  화면에서 **복사 또는 마크다운 파일로 다운로드**할 수 있으며, 실제 LLM(Perplexity/Gemini/
  ChatGPT/Claude 등) 호출은 사용자가 프롬프트를 붙여넣어 앱 밖에서 직접 수행한다 — 앱이
  자동으로 외부 LLM API를 호출하지 않는다.

### 4.7 설정 (`/settings`)
- **FR-7.0** 일반 설정: 자동 새로고침 주기, 기본 날짜 범위, 라이트/다크 테마(FR-7.6과 동일
  항목). 대시보드·상세 화면과 별개로 "일반 설정 초기화" 버튼으로 이 영역만 되돌릴 수 있다.
- **FR-7.1** 추적 종목 CRUD: 추가(티커 유효성 검증 + 종목명·섹터·뉴스 검색 키워드 자동
  제안), 수정, 삭제, 드래그 순서 변경, 검색. 목록 표는 순서·티커·종목명·타입·테마·매입가·
  수량·작업 컬럼을 보여준다.
- **FR-7.2** API 키 관리: 네이버 검색 API 키 등록(뉴스 기능 전용, 선택 사항). 등록 여부를
  "설정됨" 배지로 표시한다.
- **FR-7.3** 데이터 수집: 전체 수집 실행 + 진행률 표시, 시총 상위 카탈로그 자동 확장 수집.
- **FR-7.4** 데이터 관리: 테이블별 건수·DB 용량 통계 조회, 수집 데이터 초기화(추적 종목
  목록은 유지), 카탈로그 초기화.
- **FR-7.5** 자동 수집 스케줄러 설정: 장중 분봉 수집 주기, 전체 수집 주기(허용 범위 내에서만
  변경 가능).
- **FR-7.6** 라이트/다크 테마 전환.

## 5. 데이터 요구사항

- **소스**: 네이버 모바일 API 단일 소스. 데이터 종류별 엔드포인트는
  [README.md #데이터-출처-수집-계층](../README.md#데이터-출처-수집-계층) 참고.
- **저장**: SQLite 단일 파일(`backend/data/kgrowth.db`). 테이블 9개 —
  `stocks`(추적 종목), `prices`(일별 OHLCV), `trading_flow`(투자자별 순매수),
  `intraday_prices`(분봉), `stock_fundamentals`/`etf_fundamentals`/`etf_holdings`
  (펀더멘털 스냅샷), `stock_catalog`(발굴 유니버스), `news`.
- **수집 정책**: 빈 배열 응답은 오류가 아니라 휴장·미상장을 의미하므로 저장하지 않고
  다음 수집에서 재시도한다. 네이버 API의 `pageSize`는 최대 60이며 초과 시 400 오류.
  매매동향(`trend`)은 `page` 파라미터를 무시하고 항상 최근 ~20거래일만 반환한다.

## 6. 핵심 비즈니스 규칙

- **수익률 기준일**은 네이버증권 표기와 동일하게 맞춘다 — 주간=7일 전, 월간=전월 같은 날,
  연간(YTD)=전년도 마지막 거래일(거래일 수가 아니라 달력 날짜 기준). 기준일까지 시세가
  없으면 값을 만들지 않고 비운다.
- **추세 지속성**: `trend_r2`(직선 회귀 설명력)·`trend_mdd`(최대낙폭)·`trend_win_rate`
  (월별 양수 비율)·`trend_above_ma`(20일선 위 비율) 4개 지표를 함께 저장해 "연초대비 +지만
  실제로는 폭락 후 반등"인 종목을 걸러낸다. 임계값은 `scanner.SUSTAINED_UPTREND` 한 곳.
- **기준 거래일 정합성**: 한 행의 시세·수익률·수급은 모두 같은 거래일 기준이어야 한다.
  장 마감(15:40 KST) 전에는 당일 미확정 행을 쓰지 않는다(`timeutil.is_close_confirmed`).
- **거래량 소유권 분리**: 네이버의 두 API(일별시세/marketValue)가 같은 날 다른 거래량을
  주므로, 딥수집 대상은 일별시세가, 나머지는 marketValue가 소유한다.
- **수급 강도 판정**(인사이트): 최근 5거래일 외국인 순매수 합계를 최근 20거래일 평균
  거래량 대비 비율로 스케일링해 '지속 매수/매도'를 판정한다(고정 수량 임계값 아님).
- **섹터 자동분류**: 종목명 키워드 매칭 23개 섹터. 짧거나 포함되기 쉬운 키워드(`리츠`,
  `AI` 등)는 단어 경계 검사를 거쳐 오분류(예: "메리츠"가 "리츠"로 분류)를 방지한다.

## 7. 비기능 요구사항

- **플랫폼**: 웹(로컬 개발 서버) / macOS 데스크톱(Electron, `uv`로 백엔드 가상환경 자동 구성).
  Windows·Linux 데스크톱 빌드는 지원하지 않는다.
- **로컬 우선**: 외부 서버·계정이 없다. API 키는 로컬 JSON 파일에 저장하고 외부로 전송하지
  않는다. 모든 시세·분석 데이터는 로컬 SQLite에만 저장한다.
- **성능**: 발굴 카탈로그 전체(1,654종목, 동시성 5) 수집에 약 21분 소요. freshness 가드로
  최신 상태면 재수집을 건너뛰고, 신규 종목만 보강 수집할 때는 수 초로 단축된다.
- **표시 규칙**: 사용자에게 보이는 모든 숫자는 천 단위 구분 기호를 사용한다.
- **데이터 신뢰성**: 값이 없으면 임의로 만들지 않고 비워 둔다(네이버증권과 동일한 원칙).
  휴장·미상장 구간은 그래프·표에서 자연스럽게 빈 구간으로 남는다.

## 8. 제약사항 및 알려진 한계

- 발굴 카탈로그 중 전체 ETF + 코스피 상위 200 + 코스닥 상위 300 밖의 종목(약 2,600개)은
  수익률·수급이 항상 비어 있다. 범위를 넓히려면 수집 시간이 비례해 늘어난다(전체 확대 시
  약 55분 예상).
- 데스크톱 앱은 설치 대상 기기에 `uv`가 필요하다. 없으면 백엔드가 기동하지 않는다.
- 배포 dmg는 기본적으로 코드서명·공증이 되어 있지 않다(인증서가 있는 환경에서 빌드하면
  자동 서명, 없으면 Gatekeeper 경고 후 "확인 없이 열기"로 실행).
- 뉴스 기능은 네이버 검색 API 키 등록이 필요하며, 없으면 나머지 기능은 정상 동작하되
  뉴스 관련 화면만 비활성화된다.
- AI 투자분석은 프롬프트 생성까지만 지원한다. 실제 LLM 호출·응답 표시는 범위에 없다.

## 9. 범위 외 (Out of scope)

- 실시간 시세 스트리밍(WebSocket).
- 자동매매·증권사 주문 연동.
- 다중 사용자 인증·권한 관리.
- 해외 시장·환전.
- 앱 내 LLM 자동 호출(현재는 프롬프트 생성 + 사용자의 수동 복사/붙여넣기까지만).
